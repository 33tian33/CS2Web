# 校园竞技场 · CS2 赛事网站

可本地运行的第一版框架。无第三方运行依赖：Python 3.9+ 标准库后端、SQLite 数据库、原生 HTML/CSS/JavaScript 前端。

## 部署与初始数据

新服务器 `SERVER_IP`（Debian 13.2），使用域名 `www.hushang985.online`，程序与当前本地数据库一起迁移的完整步骤见 [Debian 13 部署教程](docs/DEPLOY_DEBIAN13.md)。后续更新程序时保留线上数据库。

已上线站点的图片迁移、缓存与压缩、裸域名 HTTPS 跳转，以及验证和回滚步骤见 [首页加载优化与部署教程](docs/PERFORMANCE_UPDATE.md)。

旧服务器 `SERVER_IP` 的空库部署方案保留在 [Debian 10 历史教程](docs/DEPLOY_DEBIAN10.md)，不适用于这次本地数据库迁移。

本地采用四校48队赛制：12组单循环BO2，前两名及成绩最好的8个第三名晋级32强；按2026世界杯官方对阵和495种第三名组合表安排淘汰路径，单淘BO3、决赛BO5、季军赛BO3，共104场。现有分组和人员保留。启动不自动生成数据；修改前备份在 `data/backups/`。现有赛事更新见 [世界杯赛制与迁移](docs/WORLDCUP_FORMAT.md)。

## 已实现

- 后台每张地图支持粘贴战绩，识别选手 ID、K/D/A 和 Rating；预览中可调整选手匹配和有歧义的数字拆分，填入后随比赛保存。
- 首页“赛场速递”以单张全宽横幅轮播北京时间当天对阵、最近完赛及独立 MVP 画面，完赛背景融入地图图片；每 6 秒切换，支持手动翻页与暂停，鼠标悬停或键盘聚焦时暂停。
- 后台编辑比赛可选择或清除本场 MVP；赛果页展示头像、昵称、队伍及本场平均 Rating、累计 K/D 与净击杀。
- 首页赛事入口；当前赛事页按对阵、Rating 榜、队伍巡礼、小组积分、淘汰赛的顺序展示。
- 队伍巡礼按复旦大学、华东师范大学、上海交通大学、同济大学切换，每校最多 12 队，队伍由后台创建。
- 队伍卡片展示队标、队名、两行自定义简介和每行两人的阵容；队员显示头像、ID、场上位置、完美段位图标及学校角标，外援显示“外”。
- 队伍详情、选手阵容、比赛详情、逐图 K/D/A 与 Rating、BP 展示。
- 后台登录、8 小时会话、退出、写入权限检查、同源校验及登录限速。
- 自定义赛事名称、日期、地点、小组数、每组人数上限、晋级名额、胜平负积分、同分排序、季军赛显示和各阶段默认 BO。
- 手动新建/编辑对阵及轮次；单场 BO2/3/5 独立设置；淘汰赛不接受 BO2。
- 比赛详情嵌入七张地图 BP 卡片：地图图片、Ban/Pick/Decider/Unused、操作队伍与 CT/T；移动端横向滚动，不提供独立导播输出页面。
- 对阵编辑内嵌 BP 设置：BO2/3/5 模板、先手方、七图地图池、开局选边、实时预览和保存；已用地图不可重复，已有赛果的地图不可通过 BP 改名。
- 赛段规划器：小组单循环、单败淘汰、单场对决；草稿保存、路径检查、启用生成赛程；参赛来源支持队伍、小组晋级名次、前序赛段比赛胜者或败者。
- 比赛详情与赛事页每 4 秒同步一次数据；后台编辑不会被轮询覆盖。
- 后台编辑地图、K/D/A 和 Rating。大比分仅由已完成地图计算；小组积分由完赛结果实时计算。
- BO2 打满两图允许平局；BO3/5 先赢 2/3 图；不兼容的 BO 切换会拒绝保存并保留原数据。
- 后台编辑队名、1–4 字简称、学校、简介、队标校徽开关及队员 ID、头像、位置、完美段位、学校；支持增减队员和本地图片上传。
- 赛事关联赞助商：后台添加、编辑、删除，支持 5MB 以内 PNG/JPG/WebP；前台页面底部以 3:2 图片自动换行居中排列，可选择居中裁切或拉伸填满并实时预览。
- SQLite 持久化；仓库包含赛事数据快照，克隆后可直接查看；数据库不存在时才初始化为空白赛事，后续启动保留修改。
- 桌面和手机响应式布局。

## 数据与规则

`data/tournament.sqlite3` 和 `data/media/` 一起纳入 Git，保存赛事数据库及上传图片的快照；后续赛事修改需提交并推送才会同步到仓库。数据库日志、备份和导入临时文件仍忽略。更新已有部署前先备份并确认数据库版本，避免覆盖本地或线上新录入的数据。

数据库位于 `data/tournament.sqlite3`，包含 settings、teams、players、matches、flow、sponsors、audit_log。sponsors.event_id 关联当前赛事 settings.id，保存名称、图片地址和适配方式。flow 分别保存草稿与已启用的赛段；matches.flow_key 将生成的比赛关联到赛段，bp_config 保存先手方和地图池。启动时自动增量迁移数据库结构，保留旧比赛与 BP 记录。地图、BP、逐图选手数据以 JSON 字段存入 matches。队标和头像单图限制 600KB，赞助商图片限制 5MB，保存到数据库旁的 `media/`，数据库仅存图片 URL。备份必须同时保存数据库和 `media/`。

已有 Base64 图片需停服后执行 `python3 scripts/migrate_images.py --database data/tournament.sqlite3`；脚本自动备份并迁移，启动服务不会自动执行图片迁移。赛事接口支持 ETag，数据未变化时返回 304；图片使用内容哈希地址并长期缓存。


`teams` 存储队标 `logo`、队名 `name`、简称 `tag`、学校 `school`、简介 `introduction` 和角标开关 `show_school_badge`。`players` 通过 `team_id` 关联队伍，存储内部编号 `id`、展示 ID `nickname`、头像 `avatar`、场上位置 `position`、所属学校 `school`、完美段位 `perfect_rank`（空字符串表示未设置）和原有身份 `role`。API 的 `player_count` 由实际阵容数量计算。队员学校独立选择四所学校或“外援”。

当前本地赛事为“四校 CS2 联赛”，48队、104场比赛；选手、时间及赛果以数据库为准。旧备份仅用于恢复，不会自动导入。

## 队标组件

`public/team-components.js` 提供共用的 HTML 渲染函数，传入 `/api/state` 中的队伍或队员对象：

```js
teamLogo(t);
teamLogo(t, true);
teamIdentity(t);
teamIdentity(t, { short: true });
teamIdentity(t, { big: true, stacked: true });
playerAvatar(p);
```

`teamLogo` 展示单独队标，第二个参数控制大尺寸；`teamIdentity` 展示队标与队名，支持简称和纵向排列。队标角标由 `t.show_school_badge` 控制；队员角标按 `p.school` 显示。校徽为本地静态素材，来源见 `public/assets/schools/SOURCES.md`。

## 赛制规则

- 默认 BO 只影响新对阵，已有比赛由单场设置决定。
- 原有独立对阵继续保留。赛段规划器生成新的赛段对阵，不会把旧比赛自动归入新赛段；同一份草稿反复启用不会重复生成比赛。比赛时间与单场 BO 可在比赛数据中调整。
- 小组赛每组 2–16 队，等额分组；单败支持 2/4/8/16/32/64 队，单场对决为 2 队。瑞士轮、GSL、双败尚未实现。
- 小组赛的「跨组比较器」可选择各组指定名次，按积分 → 净胜图 → 净胜回合降序比较；完全相同按队名、队伍编号排序。来源选齐且相关小组全部完赛、所选组内名次明确后才生效。每个比较名次可连接后续赛段位置，或设为晋级、淘汰。
- 世界杯模式下，第三名比较器的前8名由官方组合表自动分配到32强，不能再按比较名次手动连接；后台展示固定参赛来源和实际晋级对手。
- 同一组内名次不能同时直通下一赛段和进入比较器，也不能重复进入多个比较器。保存草稿可预览排名，启用后同步前台与下游对阵；已有 BP 或赛果的下游比赛继续受保护。
- 晋级来源必须来自前序赛段，同一来源不能分配两次。未使用的出口不继续晋级。小组全部完赛且所需名次无完全同分后才填入下游；淘汰赛完赛后推进胜败者。完全同分由管理员裁定，将下游来源改为指定队伍后启用。
- 草稿不会改变已启用的比赛。重建涉及已有 BP、进行中或已有赛果的对阵时拒绝修改；上游结果修改将改变已有数据的下游队伍时整次保存回滚。
- 移除赛段会把引用它的晋级位置改为待安排；补齐剩余位置后点击“应用赛制”生效。也可移除全部赛段并应用空赛制，删除无 BP、赛果且未开始的赛段比赛；独立创建的比赛、队伍和选手保留。
- 排名规则支持地图净胜、回合净胜及相互战绩积分的三种预设优先级。相互战绩积分是同总积分队伍间的小循环积分；所有配置项仍相同时按队伍编号暂排，页面提示管理员裁定。
- 地图录入只表示已结束地图；不支持逐回合实时比分。地图不允许平局。
- 比赛时间按北京时间（UTC+8）处理。服务端约每秒检查一次，到时将双方已确定的“未开始”比赛自动改为“进行中”；未设置时间、队伍待定或已结束的比赛不变。服务重启时补齐逾期状态，页面每 4 秒同步，编辑弹窗打开时暂停刷新。
- 单图 Rating 采用后台录入的「Rating」。平均 Rating 榜按已录入的逐图 Rating 算术平均，场数为有数据的地图数，分别统计全部、小组赛、淘汰赛前 30 名；赛事页只显示前 3 名，点击「查看完整榜单」进入详细榜单；未录入数据不计入，0 分正常计入。同分按场数降序、选手内部编号升序排序。
- 最高单图 Rating 榜统计整个赛事前 5 次表现，赛事页只显示前 3 名，点击「查看完整榜单」查看前 5 名，同一选手可多次上榜，包含轮次、对手和地图序号/名称。同分按比赛编号、地图序号、选手内部编号升序排序。两榜随赛事数据每 4 秒同步更新，进行中系列赛已录入的结束地图也计入。
- 当前是单赛事框架，尚未实现多赛事后台、历史阵容快照、多赛事发布流或自动 Demo 解析。
- 正式上线时需迁移生产服务、HTTPS、独立管理员凭据与持久会话、规范化地图/统计表、图片对象存储及数据库备份。

## 文件

- `server.py`：本地服务器、API、数据校验、数据库初始化。
- `public/index.html`：页面入口。
- `public/app.js`：前台、后台、积分计算及表单。
- `public/team-components.js`：队标、队标与队名、学校校徽、队员头像组件。
- `public/style.css`：深色赛事主题与响应式样式。
- `public/bp.js`：嵌入式 BP 卡片与编辑面板。
- `public/planner.js`：赛段配置、来源选择、赛程图与前台赛段展示。
- `public/comparators.js`：跨组比较器配置、排名表、晋级去向与前台展示。
- `tournament.py`：BP 规则、赛段模板、积分、晋级和数据库迁移。
